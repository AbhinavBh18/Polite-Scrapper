## Run locally

Use Python 3.10 or later. From the repository root, install the Python lane dependencies and run the scraper.

```sh
python -m pip install -r requirements.txt
python src/main.py
```

The scraper uses Requests, Beautiful Soup and Pydantic. A complete live run should produce 60 records from 3 catalogue pages and 60 detail pages. It needs internet access for cache misses. Subsequent runs reuse the cached pages.

| File | Contents |
| --- | --- |
| `output/books.json` | Validated records, replaced on every full run |
| `output/errors.json` | Skipped URLs or rejected records, with reasons |
| `output/run-report.json` | UTC start time, duration, traffic, and results |
| `cache/` | Original HTML for successful responses |

## Record schema

| Field | Type | Rule |
| --- | --- | --- |
| `title` | String | Required, nonempty |
| `product_url` | String | Canonical HTTPS detail URL and unique key |
| `price_text` | String | Original GBP text such as `£51.77` |
| `price_gbp` | Number | Nonnegative normalized price, for example `51.77` |
| `availability_text` | String | Required stock text with whitespace collapsed |
| `rating_text` | String | `One`, `Two`, `Three`, `Four`, or `Five` |
| `description` | String or null | Null when the detail page has no description |
| `source_page` | String | First catalogue URL where the book was found |
| `fetched_at` | String | UTC timestamp from the cached HTML's original write time |

## Politeness and limits

- Requests are sequential and wait at least 500 ms after the previous request completes. Each request has an eight-second connect and read timeout.
- The default user-agent identifies the assignment and author. Use `--user-agent` to include a contact URL for your published repo.
- Only HTTP 200 responses are cached and parsed. The scraper retries once on timeouts and 5xx responses. It skips 403, 404 and redirects.
- Use one running scraper process per cache. Cached HTML has no automatic expiry, so stock and price may be stale. Point `--cache-dir` at an empty directory when you intentionally need a fresh scrape.
- The data is in the server's HTML, so a browser would only add cost.
- Use an official API when one exists. Respect the site's access rules and collect only the data you need. Never bypass logins, paywalls or blocks.

## Checkpoints and evidence

```sh
python src/main.py --through fetch
python src/main.py --through discover
python src/main.py --through extract
python src/main.py
python src/main.py --simulate-missing
python -m unittest discover -s tests -v
```

Run the fetch checkpoint twice to see `FETCH` and `CACHE HIT`. The discovery and extraction checkpoints print their counts and one raw record at the extraction stage. A full rerun should yield the same 60 records. Run the fault simulation after a full run so the good pages are served from cache. The added URL produces a local simulated 404 without contacting the site. The run writes its valid records and exits with status 1 to flag the failure.

`requests_sent` counts attempted HTTP calls, including retries. `pages_fetched` counts successful HTTP 200 responses. A page that failed to fetch or extract appears under `failed_pages`, while a parsed record rejected by the schema appears under `invalid_records`.

## Publish

If you are using the archive, first run `git clone polite-scraper.bundle scraper-repo` from the archive root and then `cd scraper-repo`. Cloning the bundle restores all seven stage commits. Remove the bundle remote with `git remote remove origin` before creating the GitHub remote.

With the [GitHub CLI](https://cli.github.com/) authenticated, run this from the repo root to create and push the public repo. The sample report is tracked. The HTML cache and generated run files are ignored.

```sh
gh repo create polite-scraper --public --source=. --remote=origin --push
```
